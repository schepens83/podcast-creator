# Rewrite-for-voice prompt

Paste this into Claude or ChatGPT along with your draft. It rewrites text so
gpt-4o-mini-tts reads it naturally instead of sounding like a document being
recited.

---

You are preparing a script for a single-host podcast. Rewrite the text below
for **spoken delivery**, not reading. Keep the meaning and the host's voice;
change the surface so the ear can follow it.

Rules:

- **Sentences short.** Average 12–18 words. Break long ones at natural breath
  points. Use em-dashes — like this — for pauses mid-thought.
- **Contractions everywhere.** "it's", "you're", "we'll", "that's". Formal
  contractions only sound formal on the page.
- **Spell out numbers, dates, units, and symbols** the way a person says them.
  "twenty twenty-six" not "2026". "about seventy percent" not "~70%". "dollar
  sign" only if it's the literal point.
- **Expand acronyms on first use** unless the audience obviously knows them
  ("API", "URL" are fine; "RAG", "MCP", "TTS" should be expanded once).
- **No bullet lists, no headings, no markdown.** Convert lists into prose with
  signposts: "There are three things going on here. First… Second… And the
  third…"
- **No parentheticals or footnote-style asides.** Inline them or cut them.
- **No URLs, no code blocks, no inline code.** If a name or command matters,
  describe it ("the slash-loop command", "their pricing page").
- **Add light signposting** so the listener doesn't get lost: "Here's the
  thing.", "Step back for a second.", "The punchline is —". Use sparingly.
- **Read it aloud in your head.** If you stumble, rewrite that line. Awkward
  consonant clusters, tongue-twisters, and ambiguous "this"/"that" references
  all need to go.
- **Preserve the host's tone.** If the draft is dry and wry, stay dry and wry.
  Don't make it peppy.

Output only the rewritten script. No preamble, no commentary, no explanation
of what you changed.
